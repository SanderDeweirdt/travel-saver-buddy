# mmscan Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A CLI (`mmscan`) that pulls Miles & More award availability from the seats.aero API, prices and scores it against baselines, and writes a ranked spreadsheet.

**Architecture:** Thin synchronous httpx client with pacing, retries and a DB-backed call counter. Every API object is stored raw in SQLite. Scoring and reporting are pure functions over stored rows, so `score` and `report` cost no calls. Typer CLI, one module per concern.

**Tech Stack:** Python 3.12, uv, httpx, typer, pydantic v2, pyyaml, openpyxl, python-dotenv, pytest, ruff, SQLite (stdlib).

**Spec:** `docs/PRD.md` (the design) and `docs/superpowers/specs/2026-10-11-mmscan-design.md` (builder calls). Read both.

All paths are relative to `mmscan/`. Run every command from `mmscan/`.

## Global Constraints

- Python 3.12. Dependencies are limited to httpx, typer, pydantic, pyyaml, openpyxl, python-dotenv, pytest and ruff. Ask before adding any other.
- The API key comes only from env `SEATS_AERO_API_KEY`, loaded from a git-ignored `.env`. It must never appear in the config, logs, fixtures, reports or git history. Redact `Partner-Authorization` in debug output.
- Base URL `https://seats.aero/partnerapi/`. Auth header `Partner-Authorization`.
- Send one request at a time, at most 2 per second. Retry timeouts, 429 and 5xx up to 3 times with exponential backoff, honouring `Retry-After`. Never retry when `X-RateLimit-Remaining` is 0. 401 and 403 are fatal, with the message that API access may not be enabled for the account.
- Stop at `api.daily_call_cap` (default 300) calls per UTC day, counted in the DB.
- DB is `./data/mmscan.db`. Rows older than 180 days are deleted at the start of each run.
- Every report carries the line: `Cached data. Confirm price and seats on miles-and-more.com before acting.`
- Times are airport local time even though they end in `Z`. Never convert them as UTC.
- Tests use pytest and never touch the network.
- Every command accepts `--config PATH` (default `config.yaml`) and `--dry-run`.
- Never commit `.env`, `data/` or `reports/`. Commit at the end of each milestone, and also per task.
- Before any live API command other than `mmscan check`, state the number of calls and ask Sander.
- Do not invent API fields. If a field the PRD relies on is missing live, stop and report it.

## Review Focus

1. **Cursor pagination repeating a page forever.** A page that adds no new `ID` ends the scan with a warning. Test in Task 7.
2. **Daily cap hit mid-scan or mid-enrich.** Stop cleanly, keep what was stored, mark the run `partial`, and exit non-zero with a clear message. Tests in Tasks 4 and 9.
3. **Crash or Ctrl-C mid-enrich.** Each Get Trips result is committed as it arrives, so a rerun does not pay for it again. Test in Task 9.
4. **Zero results.** Report and score still run. Empty baselines give "unknown", with no division by zero or median of an empty list. Tests in Tasks 10 and 12.
5. **Bad `cash_fares.csv`.** A missing file means no fares. Bad rows (wrong month format, non-numeric fare) are skipped with a warning naming the line. Test in Task 11.
